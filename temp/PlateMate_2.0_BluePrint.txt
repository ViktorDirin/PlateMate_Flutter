
# ТЗ для приложения PlateMate (Flutter + Supabase)

## 1. Логика данных и иерархия
- Поддержка нескольких независимых диет (например, "Vik's Diet" и "Grey's Diet"). У каждой диеты свой ID.
- Библиотека блюд (Categories), разделенная по типам: Breakfast, Lunch, Dinner.
- Блюда содержат ингредиенты (Название, Количество, Единица измерения: гр, шт, мл).
- Сортировка Drag-and-Drop: возможность вручную менять порядок блюд в категориях.
- Интерактивное расписание (Schedule) — привязка блюд к датам календаря.

## 2. Ключевые "фишки" интерфейса и UX
- Система "Звездочка" (Приоритетный запуск): если диета отмечена звездочкой, приложение при старте мгновенно открывает именно её экран, минуя главный список диет. Кнопка "Назад" возвращает пользователя на главный экран.
- Умный ввод времени: при планировании времени приема пищи, ввод без двоеточия (например, "800" или "1420") должен автоматически форматироваться в "08:00" или "14:20".
- Таймер голодания: расчет и показ времени, прошедшего с момента последней сделанной записи в расписании на сегодня.
- Адаптивная темная тема (Глубокий черный/темно-синий фон, неоновые акценты).

## 3. Архитектура и Синхронизация
- Hybrid Loading (Мгновенный старт): при запуске данные всегда берутся из локального кэша (памяти устройства) и сразу отрисовываются. В фоне запускается запрос к Supabase. После успешного ответа данные обновляются, если есть изменения.
- Индикатор облака: иконка облака меняет цвет (Зеленый — синхронизировано с Supabase, Желтый/Красный — идет загрузка или ошибка/авиарежим).
- Логика обновлений: изменения сохраняются локально и улетают в Supabase через UPDATE конкретной строки (по ID текущей диеты), не затрагивая данные других диет.

# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (BLUEPRINT): МОБИЛЬНОЕ ПРИЛОЖЕНИЕ "PLATEMATE"

## 1. СТЕК ТЕХНОЛОГИЙ И АРХИТЕКТУРА
- **Фреймворк:** Flutter (Dart) — стабильная сборка под Android (Native APK).
- **База данных:** Supabase (PostgreSQL) для облачного хранения + локальный кэш (Hydrated BLoC или Hive/SharedPreferences) для автономного режима.
- **Особенности среды:** Полная поддержка асинхронных операций, изоляция фоновых процессов (чтобы приложение не перехватывало аудио-фокус и не прерывало музыку/видео на устройстве).

## 2. ДИЗАЙН И ИНТЕРФЕЙС (UI/UX)
- **Стиль:** Современный, лаконичный, минималистичный премиум-дизайн на основе готовых дизайн-систем Flutter (компоненты Material 3 с кастомной стилизацией). Крупные кликабельные элементы, адаптированные под управление одной рукой.
- **Тема:** Forced Dark Mode (Строгая темная тема без поддержки светлой). 
  - Основной фон: Глубокий черный/темно-синий (`#12181f`).
  - Карточки и контейнеры: Контрастный графитовый (`#1e293b`).
  - Акценты и обводки: Неоново-синий (`#00f0ff` / `#38bdf8`) и приглушенный белый для текста.
- **Адаптивность:** Жесткая фиксация интерфейса. Запрещен горизонтальный скролл страниц. Вертикальный скролл разрешен строго внутри списков блюд. Всплывающие окна ввода (модалки) должны автоматически сдвигаться в верхнюю треть экрана при появлении системной клавиатуры.

## 3. СТРУКТУРА ЭКРАНОВ И ФУНКЦИОНАЛ

### Экран 1: Главное меню (Выбор диет)
- **Элементы:** Список карточек доступных планов питания (например, "Vik's Diet", "Grey's Diet"). В правом верхнем углу каждой карточки — иконка "Звездочка".
- **Логика "Звездочки":** Пользователь может пометить одну диету как дефолтную. При следующем холодном старте приложения экран выбора диет пропускается — приложение мгновенно открывает Экран 2 (активную диету).
- **Кнопка "Назад":** Находясь на Экране 2, кнопка "Назад" в шапке профиля корректно возвращает пользователя на этот Главный экран выбора диет.

### Экран 2: Главный экран диеты (План на день)
- **Шапка:** Название текущей диеты, кнопка "Назад" (бургер/стрелка), индикатор синхронизации "Облако".
  - *Логика Облака:* Зеленый цвет — данные успешно отправлены/синхронизированы с Supabase. Желтый/Красный — процесс отправки или ошибка сети.
- **Панель навигации по дням:** Кнопки-переключатели: "Сегодня", "Завтра" и иконка календаря для выбора произвольной даты.
- **Таймер голодания:** Информационный блок, отображающий живой счетчик времени (Часы:Минуты), прошедшего с момента последнего зафиксированного приема пищи в расписании на текущий день.
- **Список приемов пищи:** Три жестких блока (Категории): Завтрак (Breakfast), Ланч (Lunch), Обед/Ужин (Dinner).
  - Внутри каждого блока отображаются добавленные блюда с указанием запланированного времени.
  - **Умный ввод времени:** При добавлении или редактировании времени, если пользователь вводит цифры без разделителя (например, "930" или "1915"), система автоматически форматирует их в валидный формат "09:30" или "19:15".

### Экран 3: Библиотека блюд и ингредиентов
- Открывается при нажатии кнопки "Добавить блюдо" или "Редактировать базу".
- Представляет собой структурированный справочник продуктов пользователя.
- **Конструктор ингредиентов:** Каждое блюдо можно развернуть и настроить его состав. Поля: "Название продукта", "Количество", "Единица измерения" (выпадающий список: гр, шт, мл).
- **Сортировка Drag-and-Drop:** Карточки блюд можно зажать пальцем и перетащить выше/ниже внутри своей категории для выстраивания приоритета.

## 4. СИНХРОНИЗАЦИЯ И РАБОТА С СЕТЬЮ (HYBRID LOADING)
1. **Старт:** Приложение мгновенно читает локальный кэш устройства и сразу отрисовывает интерфейс (TTI < 300мс).
2. **Фоновый процесс:** Параллельно запускается асинхронный запрос к Supabase (`diet_plans`). 
3. **Обновление:** При получении ответа локальные данные сверяются с облачными, обновляются в случае расхождений, а индикатор "Облако" загорается зеленым.
4. **Запись данных:** Любое локальное изменение (добавление, удаление, изменение времени, перетаскивание) мгновенно перезаписывает локальный кэш и инициирует асинхронный `UPDATE` запрос в Supabase строго по ID текущей диеты (чтобы изменения одного пользователя не влияли на данные другого).
